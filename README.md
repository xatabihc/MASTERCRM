# MasterCRM Offline 1.7 Protected Data (Android)

![Android CI](https://github.com/xatabihc/MASTERCRM/actions/workflows/android-ci.yml/badge.svg?branch=main)

**Независимое автономное приложение 1.7.** Сохраняет совместимый подписанный пакет `com.mastercrm.offline.preview`, чтобы обновлять предыдущие Preview 0.5–0.8 без потери их базы. Это **не обновление** оригинальной MasterCRM 0.9.4 — исходные Android-исходники и её сертификат подписи не восстановлены.

## Изменения 1.7

- После экспорта защищённого архива `.mcrm5` приложение **повторно открывает файл и проверяет все зашифрованные блоки, записи и фотографии** через безопасную пробную загрузку SQLite с обязательным откатом. Статус успеха появляется только после проверки.
- На главной появляется ненавязчивое напоминание сделать копию, если есть клиенты и нет подтверждённого экспорта на устройстве либо с последнего прошло 7 дней. В настройках показана дата последнего проверенного экспорта; это не фоновое копирование, не облачная синхронизация и не гарантия существования файла.
- После импорта другой базы дата последнего проверенного экспорта очищается. Пароли не записываются в настройки.
- Просмотр фотографий ограничивает размер декодируемого изображения 1600 пикселями по длинной стороне, миниатюры — 320 пикселями, снижая риск нехватки памяти.
- Добавлены JVM-тесты напоминания и Android-тесты уменьшения снимков и целостности копии с 250 синтетическими фотографиями.
- Сохранены приложение `com.mastercrm.offline.preview`, схема SQLite 2, формат `.mcrm5`, текущая подпись и режим без сети.

## Изменения 1.6

- Учёт клавиатуры, системных панелей и выреза экрана через AndroidX Insets, включая Android 15.
- Прокручиваемые формы клиента, заказа, оплаты, возврата и расхода с `adjustResize` и прокруткой к активному полю.
- Черновики этих форм, выбранный клиент, поиск, фильтры, страница и положение списка восстанавливаются после пересоздания Activity. Восстановление черновика ничего не записывает в SQLite. Пароли резервных копий не сохраняются в состоянии Activity.
- Поиск с кнопки клавиатуры; введённый запрос сохраняется при изменении фильтров. Повторное нажатие текущего раздела не сбрасывает список.
- Поля и кнопки имеют минимум 48 dp; вкладки периода и навигация растут по содержимому при увеличенном шрифте. Суммы и статусы не вытесняют соседний текст; основные кнопки читаемы в тёмной теме.
- История заказов клиента загружается страницами по 100 записей, включая сохранение страницы при повороте.
- При пересоздании Activity сохраняется выбранный заказ для PDF, пока открыт системный выбор файла.
- Выпадающие списки в формах используют выбранную светлую/тёмную тему, включая текст, стрелку и меню.
- Расход, открытый из заказа за пределами первой страницы, сохраняет выбранную привязку.
- Совместимы прежние SQLite-схема 2, форматы резервных копий и постоянная подпись. `versionCode 16`, `versionName 1.6.0`.
- CI проверяет интерфейс и SQLite на Android 14 и 15; после слияния проверяет подписанное обновление с 0.5 и 1.5.

## Что реализовано в исходниках

- Русский интерфейс: обзор, заказы, клиенты, финансы, настройки.
- SQLite: клиенты, заказы, статусы, сроки, поиск по номеру/клиенту/телефону, платежи, возвраты, расходы.
- Деньги хранятся целым количеством копеек, без ошибок округления `float`.
- Дашборд: поступления, расходы, кассовая прибыль, долги, активные и просроченные заказы.
- **Сроки заказов 0.7:** выбор даты через системный календарь, выделение заказов с истекшим сроком, отдельные экраны «Просрочено и сегодня» и «Следующие 7 дней», быстрый переход из обзора, постраничный просмотр от 100 заказов.
- Учёт сроков работает полностью локально, не требует доступа к календарю Android, фонового сервера, уведомлений или дополнительных разрешений.
- Переключение **День / Неделя / Месяц / Всё** на главной и в финансах. Учитываются реальные поступления, возвраты, расходы и число новых заказов за календарный период в часовом поясе устройства.
- Рейтинг неоплаченных заказов с переходом в карточку; долг показывается отдельно за всё время, чтобы не путать его с денежными потоками периода.
- Финансы: реальные помесячные диаграммы поступлений и расходов за последние 6 месяцев.
- Заказы со статусом «Выдан» автоматически архивируются после полной оплаты и возвращаются в «Выдан» после возврата части денег.
- Создание/редактирование клиентов и заказов, история оплат, частичные оплаты, дублирование заказов и история заказов клиента.
- **Быстрые услуги 1.1:** в новом заказе можно подставить название, описание и **последнюю** стоимость ранее выполнявшейся работы. Список ищется по истории заказов, показывает количество применений, ограничен 40 результатами и ничего не изменяет, пока пользователь не сохранит заказ. Цена и описание остаются редактируемыми.
- **Контакт с клиентом 1.1:** кнопка открытия системного набора номера в карточке клиента, без разрешения совершать звонки и без автоматического вызова.
- **Отправка сводки 1.2:** по явному нажатию открывает стандартное меню «Поделиться» Android; передаёт только номер заказа, название услуги, статус, цену, оплату, остаток и срок — без личных сведений клиента, фотографий и заметок.
- **Поиск 1.3:** заказ находится также по тексту описания. В поиске заказов и клиентов знаки `%`, `_` и `!` считаются обычными символами, а не шаблонами SQL.
- **Быстрые статусы 1.4:** в карточке заказа можно с подтверждением перейти «Новый → В работе → Готов → Выдан». Полностью оплаченный заказ переводится сразу из «Готов» в «Архив», как при обычном редактировании. Оплаты, цена, срок и клиент при таком действии не переписываются.
- **Должники 1.5:** переключатель в списке заказов показывает неархивные неоплаченные заказы по убыванию долга; работает с обычным поиском, фильтрами статусов и страницами по 100 заказов.
- **Постоянные клиенты:** фильтр от двух заказов, число заказов, поступления и текущий долг на карточке и в списке.
- Фотографии «до/после»: галерея и **системная камера** с временным приватным FileProvider, обработка EXIF-поворота, оптимизированные миниатюры, сжатие JPEG и хранение в приватной SQLite; 10 фото каждого типа на заказ. Разрешение CAMERA/хранилища не требуется.
- Защищённый экспорт/импорт копии `.mcrm` **с паролем**, включая фотографии: сжатие GZIP, PBKDF2-HMAC-SHA256 (210 000 итераций), AES-256-GCM. Соль и nonce случайные для каждого экспорта.
- Новый потоковый экспорт/импорт `.mcrm5`: ZIP с отдельными таблицами и фотографиями, шифрование AES-256-GCM по блокам 64 КиБ, без полной загрузки базы и файлов в оперативную память. [Описание формата](docs/STREAM_BACKUPS.md).
- **Проверка копии 0.8:** в настройках можно выбрать `.mcrm5`, ввести пароль и проверить весь зашифрованный архив, ссылки между клиентами/заказами, суммы и фото **без восстановления и изменения текущей базы**. Показаны количества записей; пробный импорт автоматически откатывается транзакцией SQLite.
- Для совместимости остаются отдельные кнопки старого JSON без шифрования. Формат JSON-схемы 2, совместимость с JSON-схемой Preview 1 сохранена (без фотографий).
- Импорт полностью транзакционный: ошибка сохраняет прежние данные. При импорте также проверяются итоговые оплаты против цены заказа, отрицательные балансы, обязательные имена и допустимые статусы; повреждённые копии отклоняются до завершения транзакции. Перед импортом есть предупреждение о замене.
- PDF заказ-наряда через Android `PdfDocument` (не фискальный чек).
- Тёмная и светлая темы, собственная векторная иконка.
- **Никаких разрешений на интернет**, платных API, учётных записей или внешних серверов.
- GitHub Actions: unit test, Android Lint, сборка `app-debug.apk`, проверка подписи/идентификатора/отсутствия интернет-разрешений, публикация APK и интеграционные SQLite/UI-тесты на отдельном эмуляторе. Тесты включают базу из более 1000 клиентов.
- Настроен [автоматический выпуск APK с постоянной подписью](.github/workflows/signed-preview.yml) при изменениях приложения в `main`. Сертификат SHA-256 сверяется с первым подписанным релизом 0.5; при случайной смене ключа выпуск блокируется.

**Ограничения и незавершённые проверки:** проверка на реальном Samsung Galaxy A07, отдельные сценарии с тысячами настоящих фотографий и восстановление оригинальной кодовой базы 0.9.4 остаются открытыми. Независимый пакет MasterCRM Offline прошёл CI/эмуляторные испытания, но это не независимый аудит безопасности и не гарантия совместимости со старым приложением. Подписанное обновление Preview 0.5→1.2 с сохранением тестового клиента подтверждено в GitHub Actions; новые версии проверяются отдельно перед выпуском.

## Скачивание и установка подписанной Preview через adb (Ubuntu)

Официальный канал — **Signed preview APK**, с постоянным сертификатом, закреплённым в GitHub Actions. **Не устанавливайте debug-артефакт** для обновления подписанного приложения: его временная подпись несовместима.

На Ubuntu:

```bash
sudo apt install -y adb gh unzip
gh auth status || gh auth login
adb devices -l
```

На телефоне включите **Для разработчиков → Отладка по USB**, подключите кабель и подтвердите доверие к компьютеру. Должно появиться устройство со статусом `device` (не `unauthorized`). Если подключено несколько телефонов, выберите нужный через `ANDROID_SERIAL`.

Самый простой способ — скрипт [tools/install-mastercrm-adb.sh](tools/install-mastercrm-adb.sh), он найдёт последний успешный подписанный APK на `main`, скачает его в `~/Downloads/MasterCRM_signed_latest.apk` и выполнит `adb install -r`. Скрипт **никогда не удаляет приложение** и останавливается при ошибке подписи.

```bash
gh api repos/xatabihc/MASTERCRM/contents/tools/install-mastercrm-adb.sh \
  --jq '.content' | base64 -d > ~/Downloads/install-mastercrm-adb.sh
bash ~/Downloads/install-mastercrm-adb.sh
```

Либо вручную скачать последний подписанный APK и установить:

```bash
RUN_ID="$(gh run list --repo xatabihc/MASTERCRM \
  --workflow signed-preview.yml --branch main --status success --limit 1 \
  --json databaseId --jq '.[0].databaseId')"
mkdir -p "$HOME/Downloads/mastercrm-signed"
gh run download "$RUN_ID" --repo xatabihc/MASTERCRM \
  --name mastercrm-preview-signed-release \
  --dir "$HOME/Downloads/mastercrm-signed"
adb install -r "$HOME/Downloads/mastercrm-signed/app-release.apk"
adb shell am start -n com.mastercrm.offline.preview/com.mastercrm.offline.MainActivity
```

`-r` означает обновить существующую подписанную версию **без удаления её локальных данных**. При `INSTALL_FAILED_UPDATE_INCOMPATIBLE` **не выполняйте `adb uninstall`**: сначала сохраните и проверьте резервную копию `.mcrm5`. Оригинальную MasterCRM 0.9.4 не удаляйте. Для первого запуска используйте отдельную установку MasterCRM Offline.

## Сборка в Android Studio

- JDK 17, Android SDK 35, Gradle 8.9 / Android Gradle Plugin 8.7.3.
- Откройте корневую директорию проекта как Android-проект.
- Запустите `gradle :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` с установленным Gradle 8.9.
- APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Пока Gradle Wrapper jar отсутствует. GitHub Actions самостоятельно устанавливает точную версию Gradle.

## Фотографии и резервные копии

- Фотографии хранятся внутри приватной базы приложения. Изображения при добавлении перекодируются в JPEG, удаляя исходные метаданные и уменьшая размер.
- Все фото входят как в зашифрованную `.mcrm`, так и в старую JSON-копию. В версии 0.3 защищённый экспорт имеет лимит 64 МБ исходного UTF-8 JSON и 80 МБ зашифрованного файла: это **не потоковый архив**. Если фотографий слишком много, приложение покажет ошибку и не сможет создать защищённую копию.
- Рекомендуемый формат `.mcrm` шифруется паролем. Не забывайте пароль — восстановить его невозможно. Старый JSON не зашифрован и содержит имена, телефоны, финансовые данные и фото; не храните такой файл на общедоступном диске.
- При импорте заменяется **вся** локальная база, включая фотографии. Для `.mcrm` сначала проверяется криптографическая целостность, затем JSON восстанавливается в транзакции SQLite. Перед импортом обязательно сохраните предыдущую копию.
- При обновлении Preview 0.1 → 0.2 исходная SQLite-схема расширяется *без удаления старых таблиц*. Сам APK из CI может иметь **другую подпись**, поэтому установка «поверх» может быть заблокирована Android — никогда не удаляйте Preview с данными без сохранённой копии.

## Подпись и обновления APK

Отладочные APK GitHub Actions могут иметь разные сертификаты. **Постоянный release-ключ уже создан владельцем и подключён к GitHub Secrets.** Первую подписанную Preview 0.5 успешно собрали и проверили. Начиная с версии 0.6 релиз автоматически подписывается при изменениях приложения в `main`, а сертификат сверяется с первым выпуском. Установка подписанных версий 0.5→0.8 с сохранением базы подтверждена в Android CI; тест 0.5→1.0 запускается при релизе. См. [безопасную инструкцию по подписи](docs/SIGNING.md).

Важно: даже постоянный ключ Preview не делает этот проект обновлением оригинальной MasterCRM 0.9.4, исходники и подпись которой не восстановлены.

## Безопасность

- Никаких реальных данных, БД, ключей подписи, `.env`, токенов или клиентских фото в публичном репозитории.
- `android:allowBackup="false"`: приложение не выгружает содержимое БД через автоматическое облачное резервное копирование Android.
- Резервная копия JSON содержит персональные сведения клиентов **в открытом виде** — храните её только в защищённом месте.
- Восстановление в текущей Preview-схеме не совместимо автоматически с БД MasterCRM 0.9.4.
- Не используйте Preview для реальных клиентских данных до успешных тестов на устройстве и проверки экспорта/импорта.

Подробнее: [формат защищённого архива и ограничения](docs/SECURE_BACKUP.md).
