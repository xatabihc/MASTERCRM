# MasterCRM Offline — план безопасного бета-тестирования

## Задача
Проверить реальные сценарии использования без раскрытия данных клиентов и без обещаний о надёжности, которые не подтверждены испытаниями. Версия 1.6.0 опубликована как Beta. Релиз 2.0 не считается готовым до прохождения всех нижеперечисленных этапов.

## Как зафиксировать фактический результат

- Добровольный участник публикует [обезличенный отчёт по готовой форме](https://github.com/xatabihc/MASTERCRM/issues/new/choose), выбирая «Отчёт добровольного бета-тестирования». Нельзя указывать реальные имена, контакты, пароли, фотографии или прикреплять архивы.
- После проверки достоверности и отсутствия приватных вложений отчёт добавляется в [ведомость результатов 2.0](BETA_RESULTS_2_0.md) со ссылкой на GitHub Issue.
- Если тест длился меньше семи дней, он может выявить ошибку, но **не засчитывается** как полноценное семидневное независимое испытание.
- На момент подготовки формы реальных подтверждённых семидневных отчётов не было; не выдавайте автоматические проверки за независимый пользовательский аудит.

## Кого привлекать
Предлагаемый масштаб: 10–20 **добровольных** мастеров разных направлений, на разных Android-устройствах. Тестирование не начинается автоматически: разработчик приглашает людей сам и собирает их согласие. Не запрашивать у них адреса, контакты клиентов, файлы реальных заказов или доступ к телефону.

## Первые 15 минут (с вымышленными данными)
1. Установить подписанный APK из официального GitHub Releases; открыть и закрыть приложение.
2. Создать тестового клиента и заказ, указать работу, цену, дату завершения.
3. Добавить аванс, расход, остаток оплаты, проверить долг, прибыль и статусы.
4. Добавить снимки собственного тестового предмета «до» и «после» через камеру и галерею.
5. Сгенерировать PDF; проверить внешний просмотр и возврат в CRM.
6. Изменить тему, открыть клавиатуру и повернуть телефон с незавершённой формой.
7. Создать защищённую копию .mcrm5 с уникальной парольной фразой и сохранить её отдельно.
8. Проверить копию без восстановления. **Не пробовать восстановление на телефоне с нужными данными**: только в чистой тестовой установке/эмуляторе.

## Семидневный сценарий
- Каждый день добавлять несколько **тестовых** заказов, искать по номеру, клиенту и описанию, переключать фильтры задолженности/сроков.
- Проверить изменения статуса, частичную оплату и возврат, связь расхода с нужным заказом.
- Проверить работу после принудительного закрытия приложения и после обычного обновления APK с совместимой подписью.
- Тестировать слабое освещение, длинные тексты, шрифт 130%+, светлую/тёмную тему.
- Зафиксировать проблемы через [GitHub Issues](https://github.com/xatabihc/MASTERCRM/issues/new/choose) без реальных личных данных.

## Критерии допуска стабильного релиза
- [ ] Минимум 10 добровольных участников, минимум 7 дней наблюдений, разнообразные устройства; результаты зафиксированы без персональных данных.
- [ ] Нет известных воспроизводимых потерь данных, некорректных расчётов или утечек паролей.
- [ ] Экспорт, проверка и восстановление защищённого архива прошли на **чистом тестовом устройстве**; сверены клиенты, заказы, оплаты, расходы и фотографии.
- [ ] Пройден тест на нехватку места и отказ доступа к файлу. Никакая ошибка не должна частично менять существующую базу.
- [ ] Проверены тысячи синтетических записей и большие наборы фотографий; ограничения формата задокументированы.
- [ ] Подписанное обновление предыдущей версии на эмуляторе сохраняет тестовые данные.
- [ ] Финальные JVM, Lint, Android 14/15/16 (если доступно), сборка и проверка подписанного APK успешны.
- [ ] Есть понятный экран резервного копирования и предупреждение, что приложение хранит данные локально.
- [ ] Доступны политика конфиденциальности, инструкция по установке и заметки о выпуске.
- [ ] Известные ограничения явно отражены в описании релиза; выпуск отмечен Beta, пока условия не выполнены.

## Ограничения, о которых важно предупредить
- MasterCRM Offline Preview (`com.mastercrm.offline.preview`) — **отдельное приложение**, а не обновление оригинальной MasterCRM 0.9.4.
- Нет автоматической синхронизации и облачной копии; потеря телефона без сохранённого файла .mcrm5 грозит потерей данных.
- Необходимо помнить пароль защищённого архива. Восстановить его через разработчика нельзя.
- Старый экспорт JSON не зашифрован и не подходит для пересылки реальных данных.
- Приложение не формирует фискальные чеки и не заменяет бухгалтерскую/налоговую систему.
- Тесты с синтетическими данными не гарантируют отсутствие ошибок в реальной эксплуатации.
