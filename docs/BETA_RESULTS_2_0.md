# Результаты независимого бета-тестирования MasterCRM Offline

Этот документ — публичная ведомость **фактически подтверждённых** проверок, а не список планов. Не записывайте людей в таблицу без их добровольно опубликованного отчёта; одно сообщение не заменяет семь дней использования.

**На момент создания:** количество подтверждённых независимых семидневных тестирований — **0**. Стабильный релиз 2.0 не подтверждён.

## Как собираются доказательства

1. Доброволец тестирует приложение **только с вымышленными клиентами** либо на своих данных, но не публикует их.
2. Через [новую форму GitHub](https://github.com/xatabihc/MASTERCRM/issues/new/choose) размещает обезличенный отчёт со сроком, версией, моделью и проверенными сценариями.
3. Перед добавлением в сводную таблицу проверяем, что отчёт содержит минимум семь дней тестирования, не включает приватные вложения и не противоречит сведениям о версии приложения.
4. Каждая запись таблицы ссылается на **конкретный issue**. Не учитывайте повторные отчёты одного участника как новых независимых людей.
5. Для стабильного 2.0 нужно минимум 10, рекомендовано до 20 подтверждённых отчётов на разных физических моделях с разными версиями Android. Реальный результат отмечается отдельно от автоматического CI.

## Инженерные испытания — не заменяют реальную бету

- GitHub Actions 1.8: [Android CI](https://github.com/xatabihc/MASTERCRM/actions/runs/42463689381), [подписанная сборка](https://github.com/xatabihc/MASTERCRM/actions/runs/42463689397), [обновления с сохранением тестового клиента](https://github.com/xatabihc/MASTERCRM/actions/runs/42463689450) — успешно.
- Защищённый архив .mcrm5 уже проверялся в эмуляторах с синтетическими фотографиями и пробным импортом, который откатывается.
- [Задача №26](https://github.com/xatabihc/MASTERCRM/issues/26) остаётся открытой, пока не будет подтверждён весь список критериев.
- Публикация новых подписанных APK и зелёные тесты не подтверждают автоматически отсутствие ошибок на других моделях или в длительной работе.

## Конфиденциальность

Никогда не просите отправлять исходную SQLite-базу, настоящие фотографии, пароли и ключи подписи. Публичные отчёты должны быть обезличены. Если участник случайно опубликовал персональные данные, не переписывайте их в эту таблицу и сообщите ему о необходимости удалить приватные вложения из публичного issue.
