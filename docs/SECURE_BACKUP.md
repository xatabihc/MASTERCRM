# Защищённые резервные копии MasterCRM Preview 0.3

## Использование
В настройках приложения доступны четыре действия:
- **Создать защищённую копию** — сохранение файла `.mcrm` с вашим паролем (не менее 12 символов). Пароль необходимо ввести дважды.
- **Восстановить защищённую копию** — выбор файла `.mcrm` и ввод пароля после предупреждения о замене существующих данных.
- **Экспорт JSON (без защиты)** — только для совместимости со старой Preview 0.1/0.2.
- **Импорт JSON (без защиты)** — только для совместимости со старой Preview 0.1/0.2.

Пароль не передаётся на сервер и не сохраняется в настройках приложения. Если забыть пароль, расшифровать файл невозможно. Рекомендуется пароль-фраза, состоящая из нескольких случайных слов.

## Криптографический формат v03
Файл представляет собой бинарный массив:

```
0..7     ASCII "MCRMBK03" (версия формата)
8..23    16 байт случайной соли
24..35   12 байт случайного nonce
36..N    AES-256-GCM(ciphertext + 128-bit authentication tag)
```

- Ключ получается из пароля: PBKDF2-HMAC-SHA256, 210 000 итераций, 256 бит, соль 16 байт.
- Перед шифрованием JSON (UTF-8) сжимается GZIP.
- AES-GCM шифрует GZIP и аутентифицирует **всю 36-байтную шапку** как AAD. Подмена соли, nonce или содержимого обнаруживается при расшифровке.
- Версия 03 и число итераций фиксированы. Изменения алгоритма должны использовать новый marker, а не молча заменять параметры.
- Нет хранения производного ключа или пароля. Отдельный соль+nonce создаются для каждого нового файла SecureRandom.

## Ограничения и риски
- В этой реализации JSON перед шифрованием целиком находится в оперативной памяти. **Не потоковый бэкап**. Максимум 64 МиБ UTF-8 JSON после распаковки и 80 МиБ зашифрованного файла; при больших фотоархивах нужен будущий потоковый формат.
- Шифруются только **экспортируемые резервные копии**, а не сама SQLite-база внутри телефона. Данные в приложении дополнительно защищаются средствами Android и блокировкой устройства; root-доступ может обойти эту защиту.
- Пароль-фраза важнее размера ключа: короткие/распространённые пароли подвержены подбору при наличии копии файла.
- Запись в выбранный пользователем файл зависит от SAF-провайдера (например, файлового менеджера). Не считать факт записи достаточной проверкой: рекомендуется выполнять пробное восстановление на тестовых данных.
- При импорте данные в текущей Preview **заменяются**. Даже с транзакцией при отказе устройства и повреждении хранилища существует риск потери. Сохраняйте минимум две копии в независимых защищённых местах.
- Формат `.mcrm` предназначен только для **MasterCRM Offline Preview** и не совместим непосредственно с оригинальной Android MasterCRM 0.9.4.
- GitHub Actions подписывает debug APK временным сертификатом. Не удаляйте Preview с данными ради обновления, пока не убедитесь в работоспособной резервной копии.

## Проверки
- Модульные тесты: восстановление Unicode, разные случайные salt/nonce, неправильный пароль, изменение заголовка/шифротекста, некорректный формат.
- Android-интеграционный тест: реальная SQLite-база с заказом, оплатой и фотографией → зашифрованная копия → восстановление и проверка значений.
- Эти тесты не заменяют аудит безопасности или ручную проверку на реальном устройстве.

## Оставшиеся работы для релиза 1.0
1. Потоковый ZIP-архив с ограничениями размера и количеством записей, без хранения всех фото в JSON.
2. Необязательная автоматическая проверка копии после экспорта (без изменения активной базы).
3. Постоянный приватный ключ подписи APK и политика безопасного хранения ключа.
4. Проверка миграции из реальной оригинальной 0.9.4 после восстановления исходников и её подписи.
