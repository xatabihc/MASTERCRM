# Потоковые защищённые резервные копии MasterCRM 0.5

## Новый формат `.mcrm5`

Это новый формат резервных копий **только для MasterCRM Offline Preview**. Он работает без сервера, облака и подписки.

- Записи `clients`, `jobs`, `payments`, `expenses` сохраняются в отдельных NDJSON-файлах внутри ZIP.
- Фотографии сохраняются как отдельные JPEG-записи внутри ZIP. Они больше не увеличивают строку JSON за счёт Base64.
- ZIP шифруется через последовательность независимо аутентифицированных записей по 64 КиБ. Для работы не нужен большой массив со всем архивом.
- Пароль не сохраняется. Необходимо хранить его в безопасном месте.
- При восстановлении используется транзакция SQLite: **все данные сохраняются или ни одно изменение не принимается**.
- Для коммита транзакции обязательно успешно прочитать аутентифицированный финальный маркер, а также проверить ограничения размера и целостность связанных таблиц.

## Формат шифрования MCRMBK05

В начале файла:
- 8 байт magic: ASCII `MCRMBK05`
- 16 байт случайная соль
- 8 байт случайный префикс nonce

Пароль → PBKDF2-HMAC-SHA256, 210 000 итераций, AES-256 ключ.

Затем последовательность записей: 4-байтная длина открытого текста (big-endian, 0..65536), соответствующий шифротекст и тег AES-256-GCM длиной 16 байт. Для каждой записи nonce = префикс 8 байт + 4 байта номера записи. AAD = полный 32-байтный заголовок + номер записи + длина. Последняя запись имеет нулевую длину и обязательный корректный тег. Нельзя добавлять данные после неё.

Такая схема обнаруживает неверный пароль, повреждение, перестановку или усечение зашифрованных записей. Она не является форматом ZIP AES и не совместима с обычными ZIP-архиваторами.

## Ограничения версии 0.5

- Максимальный криптографически защищённый ZIP-поток — 1 ГиБ.
- Максимум 512 МиБ суммарного содержимого после распаковки ZIP.
- Каждая фотография до 2 МиБ, не более 10 фотографий каждого типа на заказ и 10 000 фотографий на одну копию.
- Не более 100 000 записей в каждой таблице и 64 КиБ UTF-8 на одну NDJSON-запись.
- При превышении лимитов операция отклоняется. Если система вернула файл неполного экспорта, импорт его не примет.
- Это не замена файловой системе, не автоматическое фоновое копирование и не шифрование самой SQLite-базы.
- Для подтверждения совместимости между устройствами нужны тесты с реальными Android-версиями.

## Проверка архива без восстановления (Preview 0.8+)

В **Ещё → Резервные копии → Проверить копию .mcrm5 без восстановления** выберите файл и введите пароль. Приложение проверит все GCM-блоки (включая завершающий), ZIP, структуру записей, суммы оплат, связи между таблицами и JPEG-файлы. В конце покажет количество клиентов, заказов, платежей, расходов и фотографий в архиве.

Проверка выполняется на рабочем потоке. Для проверки используется **транзакция текущей SQLite-базы с обязательным откатом**: все записи из архива временно импортируются и проверяются, но транзакция не сохраняется даже при успехе. Операции CRM синхронизированы с проверкой, поэтому параллельные обращения к базе не увидят промежуточные записи. Проверка на больших архивах может быть длительной; не закрывайте приложение до завершения. Это не замена независимой копии файла и не проверка подписи APK.

## Совместимость

- Старые зашифрованные копии `.mcrm` (формат MCRMBK03) остаются доступны в разделе резервного копирования.
- Старый открытый `.json` также поддерживается, но содержит персональные данные без шифрования.
- Новый `.mcrm5` требует версии Preview 0.5 и новее. Старые Preview 0.4 его не прочитают.
- Оригинальная MasterCRM 0.9.4 не обновляется и не читает эти файлы без специальной миграции. Нельзя удалять установленную 0.9.4 ради новой Preview.

## Что проверять при восстановлении

Создайте защищённую копию, сохраните пароль и проверьте восстановление в пустой тестовой Preview/эмуляторе. Убедитесь, что совпадают количество клиентов и заказов, суммы, история оплат и фотографии. Храните минимум две независимые копии.

**Внимание о подписи APK:** GitHub CI пока делает разные временные debug-сертификаты. Без постоянной release-подписи следующее обновление Preview может потребовать удаления приложения; перед этим обязательно иметь проверенный архив данных. Подготовленный процесс безопасной подписи описан в [SIGNING.md](SIGNING.md).

## Безопасность и ограничения шифрования

Парольной фразой нужно пользоваться внимательно: файл защищён AES-256-GCM, но стойкость к подбору напрямую зависит от качества пароля. Это приложение пока не проходило независимый криптографический аудит.

Заголовок, длины, порядок записей и завершающая метка аутентифицируются. Защита от злонамеренной подмены архива без знания пароля не превращает архив в подписанный документ: обладатель пароля может создавать другие корректные архивы. Импорт дополнительно проверяет структуру ZIP, имена файлов, отношения между заказами и клиентами и суммы платежей.
